# AGENTS.md

- Flutter app is in `dkc/`; run everything from there. `scripts/check.sh` runs pub get, analyze, test and a stray-file check. No pre-commit hook (analyze has known info-level lints).
- Flutter 3.44.x / Dart ^3.12.2 (`dkc/pubspec.yaml`); CI in `.github/workflows/flutter_ci.yml` must stay in step.
- PINs: no defaults and no reserved code. First launch shows `pin_setup_screen.dart`: she picks a real PIN, a second (duress) PIN and an optional wipe code, 6-10 digits each, all typed twice, and no two codes within 2 edits of each other or sharing their first 4 digits (`AuthService.validatePins`); Settings > Change codes needs the current real PIN. A forgotten PIN cannot be recovered. Bangla digits ০-৯ count as 0-9 (`AuthService.asciiDigits`). `AuthService` stores salted SHA-256 hashes in secure storage under neutral key names (`secure_store.dart`; old names are migrated at launch).
- The calculator (`lock_screen.dart`) is the app's only face: no branded screen, lock icon or mode switch. It unlocks only through `AuthService.verifyPin` (a code, then `=`; holding `=` asks for a fingerprint if she opted in): a persisted miss counter with escalating delays (30 s to 1 h) on a monotonic clock, no wall clock or NTP; checks run one at a time. Only the real PIN clears the counter; the second PIN and the wipe code still work during a lockout. The calculator fails silently. Biometrics are opt-in and `biometricOnly`.
- The wipe (her wipe code, then `=`) closes both DBs, deletes the keys, both DB files with `-wal`/`-journal`/`-shm`, every evidence file (`.enc`, plus legacy `.bin`/`.tmp`/`.enc_audio` and plaintext `.m4a`) and the temp dir, then opens on a blank calculator. It first leaves a marker file (`WipeService.hasWiped`, not a keychain item, which iOS keeps after uninstall), so that install never shows setup again; a reinstall starts fresh.
- SOS (`trigger_panic.dart`, `background_sos_service.dart`, `silent_alert_service.dart`): SMS, vibration, the status notice and OEM battery links live in the `hardware_sos` plugin (Kotlin JVM tests: `cd dkc/android && ./gradlew --offline :hardware_sos:testDebugUnitTest`). Power-button, shake and the second-PIN alert are each opt-in; every trigger except the second PIN waits `sosCancelWindow` (5 s); leaving the in-app countdown sends at once, silently (`PanicScreen.unattendedSms`); background and second-PIN sends use `dispatchSilentSms`, which never opens Messages. Never report a send as sent unless the network accepted it. Notices stay plain, low-importance and `VISIBILITY_SECRET` (tested for giveaway words in `sos_triggers_test.dart`).
- Evidence files: `EncryptionService` writes AES-256-GCM in 64 KiB chunks and returns the SHA-256 of the plaintext from the same pass. Never re-encode or strip an original before hashing it. Old AES-CTR files are rewritten on first read; keep that path and its test. Decrypted audio lives only in `<temp>/playback` while playing (`TempFiles`).
- Real and decoy vaults are separate SQLCipher files with separate keys and table names (`database_service.dart`). Emergency contacts live only in the real DB.
- Tests have no platform plugins: `dkc/test/helpers/fakes.dart` mocks the secure-storage, path_provider and sqflite channels. Secure-storage errors propagate (fail closed); there is no in-memory fallback.
- Launcher label, Recents title, iOS display name and icons say "Calculator"; strings shown outside the vault stay neutral (`lock_screen_test.dart` checks en and bn). What reviewers are told: `dkc/STORE_REVIEW.md`.
- Do not commit `build/`, `.dart_tool/` or `.DS_Store`. Do not edit `judge.md`; it holds status and gaps.
